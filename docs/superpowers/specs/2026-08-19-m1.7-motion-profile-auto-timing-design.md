# M1.7-A Motion Profile + Auto Timing 设计规范

## 1. 状态与目的

本文定义 Dexterous Robot Framework 的 **M1.7-A Motion Profile + Auto Timing** 架构演进。

M1.7-A 的目标不是替换现有轨迹算法，也不是引入完整运动规划框架，而是把“运动时间的 authority”从 Task 配置中的人工 `duration_s` 拆出来，建立一套 backend-neutral 的运动约束与自动定时层：

```text
Device / Software Limits
          ×
Motion Profile
          ↓
Resolved Effective Limits
          ↓
Minimum-Jerk Auto Timing
          ↓
Executable Segment Duration
          ↓
Existing Controller / Skill / Runtime
```

当前冻结基线为：

```text
m1.6-motion-pacing-height-v1
```

M1.7-A 必须保留 M1.6 已验证的任务语义、抓取几何、抓取物理阶段、Isaac backend 行为和 Golden 验收条件，只改变 free-space / carry motion 的 timing authority 与配置边界。

如果 M1.7-A Golden revalidation 成功，下一阶段优先进入 **M2 MuJoCo backend**，而不是立即推进 waypoint blending。

---

## 2. 已锁定的设计原则

### 2.1 Device/Hardware Limit、Project Software Limit 与 Motion Profile 分离

限制分成三种语义：

1. **Vendor / device authority limit**：有厂商、设备模型或其他明确权威来源的数据。
2. **Project software limit**：项目为兼容性、安全性或控制策略定义的保守软件边界，不冒充厂商硬件极限。
3. **Motion Profile scaling**：某类动作在上述能力边界内使用多少比例；profile 不得扩大 limit。

关系为：

```text
Authoritative Limit
       ×
Profile Scale (0 < scale <= 1)
       ↓
Effective Limit
```

Motion Profile 不是设备能力事实来源。

### 2.2 Device Model 与 Kinematic Limits 分离

现有 `Wam7Model` 保持逻辑设备模型职责，不直接塞入运动限制值。

配置层分离为：

```text
configs/devices/arms/wam7.yaml
    = device identity / frames / logical model

configs/devices/arms/wam7_kinematic_limits.yaml
    = joint kinematic limits + provenance

configs/motion/profiles.yaml
    = task-independent motion policies
```

### 2.3 Task config 必须 backend-neutral

`TabletopGraspLiftTask` 的 schema 与 loader 不再属于 `backends/isaac/config.py`。

目标边界：

```text
Task Config
  ├── geometry
  ├── initialization
  ├── task semantics
  ├── grasp semantics
  └── selected motion profile names

IsaacBackendConfig
  ├── physics_dt
  ├── USD / PhysX paths
  ├── transform sync
  └── Isaac drive profiles

MuJoCoBackendConfig (future)
  └── MuJoCo-specific execution settings
```

Isaac 与未来 MuJoCo 必须能够消费同一份 backend-neutral Task v2 语义。

### 2.4 M1.7-A 只做必要约束，不实现完整运动规划器

M1.7-A：

- Joint-space Approach：真正使用 joint limits 做 minimum-jerk auto timing。
- Cartesian Lift：真正使用 Cartesian software limits 做 minimum-jerk auto timing。
- Cartesian → joint：记录 commanded joint velocity / acceleration evidence，但暂不做完整 trajectory retiming。
- Grasp：保持原有接触、preload、lock 语义，不强行 Motion 化。

## 3. 参考设计来源与采用范围

M1.7-A 借鉴成熟项目的设计思想，但不搬入其完整体系：

- **Ruckig**：约束输入、同步、多 DoF timing、未来 jerk-limited trajectory generator 的接口思想。
- **MoveIt 2**：robot limits、scaling、time parameterization、trajectory processing 分层。
- **Pilz Industrial Motion Planner**：joint synchronization、Cartesian translation/rotation 约束、semantic stop 与 blending 边界。
- **Tesseract**：planner / time-parameterization / pipeline 模块边界。
- **Drake**：Cartesian 与 joint limits 同时存在、不能相互替代的设计思想。

M1.7-A 不直接增加 Ruckig、MoveIt、Tesseract 或 Drake 依赖。

## 6. Limit Authority 模型

### 6.1 基本数据类型

建议定义明确的 provenance-bearing limit value：

```text
LimitValue
├── value
├── authority
├── source
└── derived_from (optional)
```

`authority` 至少支持：

```text
vendor
project_software
```

### 6.2 Vendor limit

只有在存在可靠来源时才可标记 `vendor`。

示例语义：

```yaml
velocity:
  max_rad_s: <value>
  authority: vendor
  source: <document-or-asset-authority>
```

不得为了填满 schema 而猜测 vendor acceleration / jerk。

### 6.3 Project software limit

对于没有可靠厂商 acceleration / jerk 的情况，M1.7-A 初始值采用：

```text
M1.6 commanded motion envelope
           +
明确兼容/保守裕量
           ↓
project software limit
```

并写明：

```yaml
acceleration:
  max_rad_s2: <value>
  authority: project_software
  derived_from: m1.6-motion-pacing-height-v1
```

`derived_from` 是 provenance，不是 vendor authority。

### 6.4 WAM7 joint limits 配置

目标 schema 形式：

```yaml
schema_version: 1
kind: JointKinematicLimits
device_model: wam7

joints:
  wam_j1_joint:
    velocity:
      max_rad_s: <value>
      authority: <vendor-or-project_software>
      source: <source>
    acceleration:
      max_rad_s2: <value>
      authority: project_software
      derived_from: m1.6-motion-pacing-height-v1
    jerk:
      max_rad_s3: <value>
      authority: project_software
      derived_from: m1.6-motion-pacing-height-v1
```

所有 7 个 joint name 必须与 `WAM7_JOINT_NAMES` exact match；缺失、额外、重复或无穷值 fail-closed。

## 7. Cartesian Software Limits

当前 M1.7-A 的 Cartesian motion 只有 world-Z、fixed-orientation lift。

因此第一版只正式执行 linear limits：

```text
linear velocity
linear acceleration
linear jerk
```

这些值属于 `project_software` authority，不冒充 WAM vendor TCP capability。

配置可以与 motion profiles 分开或由 limits loader 统一加载，但类型必须与 joint limits 分离：

```text
JointKinematicLimits
CartesianKinematicLimits
```

未来 arbitrary Pose-to-Pose 时可以扩展：

```text
angular velocity
angular acceleration
angular jerk
```

但 M1.7-A 不实现 orientation trajectory。

---

## 8. Motion Profile 模型

### 8.1 Joint 与 Cartesian profile 分离

不使用万能 `MotionProfile`。

```yaml
schema_version: 1
kind: MotionProfiles

joint_profiles:
  approach_precise:
    velocity_scale: <0..1>
    acceleration_scale: <0..1>
    jerk_scale: <0..1>

cartesian_profiles:
  carry:
    linear_velocity_scale: <0..1>
    linear_acceleration_scale: <0..1>
    linear_jerk_scale: <0..1>
```

### 8.2 Scale 约束

所有 scale 必须满足：

```text
0 < scale <= 1
```

不得使用 profile 放大设备/软件 limit。

### 8.3 Profile 语义

M1.7-A 只要求至少存在：

```text
approach_precise
carry
```

不要为了未来场景预先增加大量 profile。

---

## 9. Effective Limits

解析流程：

```text
base limit
   ×
profile scale
   ↓
effective limit
```

对于 joint i：

```text
v_eff[i] = v_limit[i] * velocity_scale

a_eff[i] = a_limit[i] * acceleration_scale

j_eff[i] = j_limit[i] * jerk_scale
```

对于 Cartesian carry：

```text
v_eff_linear = v_limit_linear * linear_velocity_scale

a_eff_linear = a_limit_linear * linear_acceleration_scale

j_eff_linear = j_limit_linear * linear_jerk_scale
```

Resolved limits 应是 immutable value object，可独立测试；Skill 不直接读取 YAML。

## 10. Task schema v2

### 10.1 v1 现状

M1.6 Task v1 使用人工 duration authority：

```yaml
approach:
  waypoint_duration_s: 1.0

lift:
  delta_world_z_m: 0.08
  duration_s: 3.5
```

### 10.2 v2 目标

M1.7-A 当前主线配置升级为：

```yaml
schema_version: 2
kind: TabletopGraspLiftTask

control:
  approach:
    lateral_ready_q_rad: [...]
    transit_q_rad: [...]
    pregrasp_q_rad: [...]
    grasp_q_rad: [...]
    motion_profile: approach_precise

    preshape_hand_q_rad: [...]
    preshape_duration_s: 1.0
    settle_duration_s: 0.2
    joint_tolerance_rad: 0.03

  grasp:
    base_preload_hand_q_rad: [...]
    release_settle_s: 0.2
    preload_duration_s: 3.0
    lock_ramp_duration_s: 1.5
    lock_hold_duration_s: 0.5
    target_squeeze_n: 0.45

  lift:
    delta_world_z_m: 0.08
    motion_profile: carry
    minimum_object_rise_m: 0.025
    max_table_normal_n: 0.1
    max_relative_drift_m: 0.03

  hold:
    duration_s: 1.0
    minimum_clearance_m: 0.001
    max_table_normal_n: 0.1
    max_relative_drift_m: 0.03
```

### 10.3 v2 删除的 timing authority

正式主线 v2 删除：

```text
approach.waypoint_duration_s
lift.duration_s
```

### 10.4 继续保留的 duration

以下 duration 不属于 free-space motion timing，因此继续保留：

```text
preshape_duration_s
settle_duration_s
release_settle_s
preload_duration_s
lock_ramp_duration_s
lock_hold_duration_s
hold.duration_s
```

### 10.5 不提供 generic duration override

v2 不允许：

```yaml
lift:
  motion_profile: carry
  duration_s: 3.5
```

否则会产生 profile authority 与 duration authority 冲突。

如果未来需要最短执行时间，另行设计显式 `minimum_duration_s`，不复活 generic `duration_s` override。

## 11. Task loader 迁移

### 11.1 Backend-neutral location

当前 Task loader 从 Isaac config 中拆出，进入：

```text
src/dexterous_robot/config/tasks/tabletop_grasp_lift.py
```

`backends/isaac/config.py` 只保留 Isaac-specific configuration。

### 11.2 Legacy v1 兼容

新 loader 必须能够识别：

```text
schema_version: 1
schema_version: 2
```

但兼容边界集中在 config package。

禁止把以下分支传播到 Skill / Controller：

```python
if schema_version == 1:
    ...
else:
    ...
```

主线 runtime 只消费统一的 current config model。

### 11.3 Migration semantics

v1 的 `duration_s` 仍然代表 legacy authority。

v2 的 `motion_profile` 代表 current authority。

不得把 v1 duration 静默解释成 profile 参数。

## 12. Minimum-Jerk Timing

当前位置插值保持：

```text
s(u) = 10u^3 - 15u^4 + 6u^5
```

M1.7-A 新增的是自动计算 segment duration。

对位移幅值 `d >= 0`：

```text
T_v = 1.875 * d / v_max
T_a = sqrt(5.77350269 * d / a_max)
T_j = cbrt(60.0 * d / j_max)

T = max(T_v, T_a, T_j)
```

`timing.py` 必须提供纯函数级接口，可不依赖 Task、Skill、Backend 或 simulator。

---

## 13. Joint-space Approach Auto Timing

### 13.1 Waypoint 语义

`ArmWaypoint` 从：

```text
name
q_rad
duration_s
```

变为：

```text
name
q_rad
```

Duration 不再属于几何 waypoint。

### 13.2 Segment start authority

每一段开始时使用实际 snapshot joint state：

```text
q_start = actual arm state at segment start
q_target = waypoint q
```

而不是只用理论前一个 YAML waypoint。

这是为了继承已有 tracking error，并保持实际轨迹连续。

### 13.3 7 轴同步

对每个 joint i：

```text
d_i = abs(q_target[i] - q_start[i])
T_i = max(T_v_i, T_a_i, T_j_i)
```

最终：

```text
T_segment = max(T_1 ... T_7)
```

所有关节继续使用同一个 minimum-jerk normalized fraction，因此同步到达 waypoint。

### 13.4 Existing controller preservation

`JointTargetRampController` 继续负责：

```text
(start, target, elapsed, duration)
→ minimum-jerk joint command
```

M1.7-A 不重写该 interpolation algorithm，只改变谁产生 `duration`。

---

## 14. Zero-motion 与最小 segment duration

如果某一 joint `d_i = 0`，该 joint timing contribution 为 0。

如果整个 segment 的 displacement 在数值容差内为 0，则不能给现有 controller 传 `duration = 0`。

M1.7-A 定义一个明确的 numerical timing policy：

```text
minimum_segment_duration_s >= one control interval
```

其作用仅是避免零 duration / 除零与保持控制语义稳定；它不是人工 Task motion duration。

具体数值由 runtime/control interval 在实现计划中确定并纳入单元测试。

---

## 15. Cartesian Lift Auto Timing

### 15.1 当前 motion contract

M1.7-A 当前 Lift 保持：

```text
world-Z only
fixed orientation
```

### 15.2 Duration computation

第一次 Lift step：

```text
locked TCP pose
      +
delta_world_m
      ↓
distance = norm(delta_world_m)
      ↓
Cartesian effective limits
      ↓
minimum-jerk auto timing
      ↓
T_lift
```

### 15.3 Executable goal

`duration_s` 可以继续存在于已经解析后的 executable `CartesianCarryGoal` 内部。

区别是：

```text
Task config duration authority   ❌
Planner-computed executable T    ✅
```

M1.7-A 不为了删除 `duration_s` 字段名字本身而扩大重构。

### 15.4 Future orientation

未来 arbitrary Pose-to-Pose 运动时，应分别计算：

```text
T_translation
T_rotation
```

并使用：

```text
T_final = max(T_translation, T_rotation)
```

但当前 fixed orientation，因此 M1.7-A 不实现 rotation timing execution。

---

## 16. Grasp 语义边界

M1.7-A 不把 Grasp 当作 free-space arm motion。

继续保留：

```text
release settle
preload duration
lock ramp duration
lock hold duration
GraspLock latch
```

原因是这些参数表达真实接触建立、preload、lock 稳定等物理阶段。

未来如果增加 hand-side profile，应是独立概念，例如：

```text
HandClosingProfile
ForceRampProfile
```

而不是复用 Arm Motion Profile。

---

## 17. Semantic Boundary

连续运动优化不能穿过任务物理 gate。

M1.7-A 保持：

```text
Approach
  ↓ hard semantic transition
Grasp
  ↓ physical contact / preload / lock
Lift
  ↓
Hold
```

M1.7-A 不引入任何跨 `Approach → Grasp` 或 `Grasp → Lift` 的 blending。

## 18. Joint-rate Audit

### 18.1 位置

新增 backend-neutral：

```text
src/dexterous_robot/motion/audit.py
```

不得放进 Isaac backend。

### 18.2 输入

Audit 消费：

```text
time_s
JointPositionCommand
```

维护前一时刻：

```text
q_prev
qdot_prev
```

### 18.3 Evidence

计算 commanded：

```text
qdot[k]  ~= (q[k] - q[k-1]) / dt
qddot[k] ~= (qdot[k] - qdot[k-1]) / dt
```

记录：

```text
per-joint peak commanded velocity
per-joint peak commanded acceleration
overall peak utilization
limiting joint
```

### 18.4 Jerk evidence

M1.7-A 不把三阶 finite-difference joint jerk 作为正式 Golden evidence，因为它对 dt、浮点和 IK 微变化敏感。

Planner-level theoretical minimum-jerk jerk constraint仍然保留。

Cartesian→joint jerk audit 推迟。

## 19. Audit classification 与 fail-closed policy

### 19.1 Hard structural failures

以下必须 BLOCK：

```text
NaN
Inf
non-positive limits
invalid profile scale
joint-name mismatch
invalid config schema
impossible discontinuity / malformed command sequence
```

### 19.2 Software-limit exceedance

M1.7-A 对 Cartesian→joint observed qdot/qddot 超过 project software limit 时：

```text
MOTION_LIMIT_AUDIT_REVIEW_REQUIRED
```

但不自动否定物理 Golden。

### 19.3 Physical Golden 与 Motion Audit 分离

Evidence 至少分两条：

```text
PHYSICAL_TASK_GOLDEN
MOTION_LIMIT_AUDIT
```

这是有意设计，避免在第一版把架构验证和后续 full retiming 混为一个 gate。

## 21. M1.6 Compatibility Calibration

### 21.1 原则

M1.7-A 第一版不以“更快”为目标。

目标是：

```text
architecture authority changes
while
physical behavior remains near M1.6
```

### 21.2 Initial software limits

acceleration / jerk 等缺少 vendor authority 的值，从 M1.6 commanded motion envelope 派生，再加明确兼容/保守裕量。

### 21.3 Profile calibration

不要采用：

```text
software limit = old envelope
profile scale = 1.0
```

而应使用：

```text
software limit = old envelope + margin
profile scale < 1
```

使：

```text
software limit × profile scale ~= M1.6 effective envelope
```

这样 software limit 与 policy 语义保持分离。

### 21.4 Lift reference

M1.6 当前 Lift 语义：

```text
delta_world_z_m = 0.08
duration_s = 3.5
```

它可作为 M1.7-A compatibility reference，不作为 WAM vendor capability。

## 22. Error Handling

所有新配置 loader 与 timing function 必须 fail-closed。

典型错误分类：

```text
KINEMATIC_LIMITS_SCHEMA_INVALID
KINEMATIC_LIMITS_JOINT_SET_INVALID
KINEMATIC_LIMIT_VALUE_INVALID
KINEMATIC_LIMIT_AUTHORITY_INVALID
MOTION_PROFILE_SCHEMA_INVALID
MOTION_PROFILE_SCALE_INVALID
MOTION_PROFILE_NOT_FOUND
MOTION_TIMING_INPUT_INVALID
MOTION_TIMING_LIMIT_INVALID
TASK_CONFIG_SCHEMA_INVALID
TASK_CONFIG_MOTION_PROFILE_INVALID
```

具体字符串可以在实现时按当前项目已有 error naming convention 收敛，但必须：

- deterministic；
- unit-testable；
- 不静默 fallback；
- 不自动猜 missing limits；
- 不自动把未知 profile 当默认 profile。

## 31. 设计结论

M1.7-A 的核心不是“换一种轨迹算法”，而是：

> **把运动时间的 authority 从 Task 中移出：设备/软件 Limits 定义能力边界，Motion Profile 定义动作策略，Minimum-Jerk Timing 自动产生 executable duration；Task、Skill、Controller、Runtime 与 Backend 各自只保留应有的语义。**

在这一边界内，M1.7-A 应尽量复用 M1.6 已验证的 minimum-jerk、IK、Task state machine、GraspLock 与 Isaac Golden 物理链路，并把新的 Motion abstraction 作为进入 MuJoCo 之前的最后一层架构整理。
